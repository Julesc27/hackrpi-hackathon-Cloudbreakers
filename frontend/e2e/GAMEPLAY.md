# Cloudbreakers playable-game contract for CI and browser agents

This describes the implemented game, not the aspirational design in `backend/advisor/context.md`. Read `src/game/engine.js` and `src/game/data.js` for the authoritative rules before adding a scenario. Browser agents should interact through visible controls; reading the save is for assertions, not for advancing play.

## Run locally and in CI

From `frontend/`: `npm ci`, `npx playwright install chromium`, `npm test`, `npm run test:e2e`. Playwright launches Vite on `127.0.0.1:4173` with no backend. `.github/workflows/ci.yml` runs on pull requests; on pushes to main, `.github/workflows/deploy.yml` runs it first and only deploys if it passes. It checks that the committed save checkpoints match the generator, runs frontend and agent-harness unit tests, builds, runs Chromium and uploads failure traces/screenshots, and runs the backend and deploy-hook tests. To update checkpoints after a rules change, run `npm run checkpoints`, review the JSON diff, and commit the fixtures with the change.

## Saves and setup

Game state is version 5 in `localStorage['cloudbreakers-save-v1']`. `GameProvider` loads it on startup, migrates versions 2/3/4/5/4/5, and persists every change without UI-only toasts. Each browser test gets a fresh context and seeds localStorage using `page.addInitScript` *before* navigation. `localStorage['cloudbreakers-guest']='1'` suppresses the account prompt if a backend is configured. No account, network access, or production data is needed for these guest tests. Do not seed `cloudbreakers-save-owner`, `cloudbreakers-save-dirty`, or an auth token for guest scenarios. Logged-in cloud-save behavior needs separate backend integration tests.

Checkpoint JSON in `e2e/checkpoints/` is generated by `e2e/generate-checkpoints.js` with `createInitialState` and `gameReducer`; never hand-edit resources, XP, completed missions or unlocks. Checkpoints have `seenIntro: true` so milestone tests start at the map without the intro/tutorial overlay. `new-town` has no missions complete; `shelter-built` has completed First Steps; `anchor-ready` has an anchor and enough wood for a rope bridge. `seenIntro` is persistent, but `tutorialStep`, active drawer and placement selection are React UI state and cannot be resumed from a save file. The tutorial smoke test instead starts with `seenIntro: false` and clicks through the early steps.

## Implemented rules and observations

- This is action-driven, not turn-driven. Successful Gather wood, Harvest, Build, Build bridge, Repair, Upgrade, or Restore beacon actions run settlement production/consumption and grant 10 XP. A rejected action and viewing/closing panels do not advance the settlement. No End Turn action exists. Weather changes with level; there is no real-time waiting for production.
- Initially New Haven has 24 wood, 30 water, 24 food, 12 energy, 40 coins, 6 residents, XP 0 and two fixed starter buildings. Level 2 starts at 100 XP; higher thresholds and unlocks are in `LEVELS` in `src/game/data.js`.
- Missions complete automatically when their predicates become true. Building a Shelter completes `firstSteps` (+50 XP and +25 coins). Building a Bridge Anchor completes `anchor` (+30 XP). Connecting any resource island completes `firstBridge` (+100 XP and +30 coins). Resource streak quests may complete as side effects of other actions; do not assert an exact total number of completed missions unless the scenario needs it.
- A Shelter costs 10 wood, needs a free New Haven plot, and expands housing. Bridge access costs 8 wood as a one-time workshop upgrade, takes no plot, and is required before any bridge. Gather wood adds 6 wood before the action's normal production/consumption. The Verdant Reach rope bridge costs 14 wood. Exact costs and route definitions live in `src/game/data.js`, not in the design document.
- The save records resources, XP, buildings, bridges with condition, connected/discovered islands, completed mission IDs, flags, counters, weather, population, happiness, sustainability and journal entries. For browser tests assert both the visible UI result and relevant saved fields so a misleading animation alone cannot pass.

## Browser navigation for an agent

1. From `new-town`, click `[data-tutorial="island-newHaven"]` (SVG hit area), then click `[data-tutorial="gather-wood-btn"]` in the New Haven drawer. Verify wood and XP increased in the save. The drawer may cover the map until closed.
2. Click `[data-tutorial="rail-build"]` (left rail). In Town Workshop click `[data-tutorial="build-btn-shelter"]`; it enters placement mode. Click `[data-tutorial="plot-newHaven"]` (glowing map plot). Verify a shelter exists and `completed` includes `firstSteps`. The Quest Book button `[data-tutorial="rail-quests"]` opens the Captain's Log showing mission progress.
3. From `shelter-built`, open Build and click `[data-tutorial="build-btn-bridgeAnchor"]` (Unlock bridges). The Bridge routes dialog opens immediately, with no placement step. Verify `anchor` completed and the upgrade uses slot -3.
4. From `anchor-ready`, click Verdant Reach's map label (the second `.skymap .isle-hit .isle-label` in current map order), choose `Plan a bridge`, then the `Rope & Plank` card's `Build bridge` button. Verify `connected` includes `verdant`, a `verdant-haven` bridge exists, and `firstBridge` is completed.
5. For the tutorial, start with `seenIntro: false`, click the chapter intro's `Let's begin`, then the tutorial welcome's `Let's Begin`. The early guided sequence requires opening New Haven, gathering wood, opening Build, selecting and placing a Shelter, and opening Quest Book. Subsequent tutorial steps explain resources, weather, level, town statistics, Cloud advisor, map, journal, storage and settings. Use the dialog's current prompt and spotlight target instead of setting `tutorialStep` directly.

Use Playwright locator clicks, not `dispatch`, DOM `.click()` injection or forced clicks; this checks whether a player can actually reach the next step. Wait for visible dialogs and poll the persisted save rather than sleeping a fixed duration. When a path fails, inspect Playwright's trace and screenshot; then reproduce with the checkpoint named in the failed test. The advisor in `src/game/advisor.js` is local rule-based; `POST /advisor` is not implemented on the backend.

## If a browser agent is unsure what to do next

- Open the Quest Book with `[data-tutorial="rail-quests"]` or the objective ribbon at the top. In the Captain's Log, read the first active (not locked or completed) quest's objective, reward, and `current/goal` progress. Click `Continue Quest` to be taken toward Build, the map, New Haven, or storage, depending on the mission. It does not itself perform the action. If a quest is locked, read its prerequisite instead of trying to click through it.
- Open Cloud with `[data-tutorial="rail-advisor"]` and read the current suggestion, reason, trade-off, and optional alternative. `Ask again` cycles through other suggestions; use it when the first suggestion does not match the current objective. When `Show route` is enabled, click it to inspect a bridge plan; it does not build the bridge. The recommendation itself is also clickable when it has a route. Cloud's confidence percentage is a hardcoded rule-based hint, not a measured probability or a guarantee.
- Open the bottom-bar Map (`[data-tutorial="nav-map"]`) to compare reachable islands, connection costs and production. The `Chart Route` button on an island card opens its bridge options. Open New Haven to gather wood or restore the beacon; open Build to check whether an item is locked, unaffordable, or already built. If a button is disabled, read its label/cost and inspect the save before deciding how to earn resources or unlock it.
- After taking a suggested action, reopen the Quest Book and verify its progress or completed status, plus the relevant save fields. Do not treat a panel navigation, advice text, or a disabled action as completed gameplay. If the tutorial overlay is active, follow its spotlight and prompt first; the overlay may block unrelated controls. Press Esc or the panel's Close button to get back to the map.
